- `components/board/BoardCanvas.tsx` uses a client-only `next/dynamic` Excalidraw import with `ssr: false` and switches to `SvgBoard` after load or render failure.

- `lib/board/ops.ts` implements shared `applyOperation` handling for `add_text`, `add_shape`, `update_label`, `highlight`, and `clear_highlight`; both renderers consume the same replayed `BoardScene`.

- `components/board/BoardToolbar.tsx` and `app/lesson/[id]/LessonClient.tsx` wire Play, Pause, and Replay to Board Tutor narration steps.

- Auth middleware guards `/app` and `/lesson/*`, redirects AAL1 users through `/verify-2fa`, and the dashboard opens a saved Binomial Squares lesson.
- Supabase/Gemini missing configuration is surfaced in the auth/dashboard/lesson UI or API error response.

## Root cause and reachability fix

The intended flow depended on a completed Supabase session and AAL2 cookie state, while configuration failures were only safe when pages reached their client-side checks. The authenticated route itself was already correctly guarded, but the demo needed a clear, explicit click-through and renderer failure path. The current flow is: `/` Start lesson → `/signup` or `/login` → `/verify-2fa` → `/app` → Binomial Squares Start/Open → `/lesson/{sessionId}`. Missing Supabase configuration is shown by `AuthNotice`; missing Gemini configuration is returned as a visible lesson error after Play.
